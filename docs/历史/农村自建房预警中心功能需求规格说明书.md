## 模块总体说明

预警中心模块承接农村自建房隐患的"上报 → 核实 → 分发 → 处置 → 验收 → 销号"全生命周期闭环管理。模块内各页面共享统一的隐患状态机与等级口径：

**隐患流转状态（6 节点）：** 隐患上报 → 待核实 → 待分发 → 处置中 → 待验收 → 已销号；驳回分支：已驳回（退回重新整改）。

**隐患等级口径（三分类归一）：**

| 标准等级 | 徽标颜色 | 历史名称映射 |
|---|---|---|
| 严重安全隐患 | 红 | 重大隐患、较大隐患、疑似危房、严重损坏房、第三类 |
| 一定安全隐患 | 黄 | 一般隐患、一般损坏房、带轻微瑕疵、第二类 |
| 未发现安全隐患 | 蓝 | 第一类、完好房(基本完好房)、安全、无风险 |

**状态标签颜色：** 待核实（红）、待分发（橙）、处置中（蓝）、待验收（紫）、已销号（绿）、已驳回（灰）。


# 第 1 章 风险隐患管理（rural-warning-management.html）

## 1.1 功能概述

风险隐患管理页是预警中心模块的列表总览页，面向业务人员与管理员提供农村自建房隐患的集中查询、状态分桶与流程入口跳转能力。页面标题为"农村自建房 - 风险隐患管理"，无面包屑，顶部提供"业务视图 / 管理员视图"双视图切换栏。

- **视图模式**：通过 URL 参数 `?view=admin` 进入管理员视图（仅查看全流程流转情况，不产生审批或处置操作）；业务视图为默认视图。切换时使用 `history.replaceState` 同步 URL。
- **数据来源**：`js/house-arch-data.js` 的 `initHouseArchSeed()` + `getAllHouseRecords()`，过滤 `(houseType || category) === '农村自建房'`，排除来源为"物联自动上报""专家研判"的记录，并补充 2 条"待验收"模拟数据（NF-2025-00022、NF-2025-00080）。
- **顶部 KPI 卡片（3 张）**：

| 卡片 | 顶部边色 | 统计口径 |
|---|---|---|
| 存在严重安全隐患（隐患存量 · 第三类） | 红 | 重大隐患 + 较大隐患 + 第三类 |
| 存在一定安全隐患（隐患存量 · 第二类） | 黄 | 一般隐患 + 第二类 |
| 存在未发现安全隐患（隐患存量 · 第一类） | 蓝 | 第一类 + 安全 + 无风险 |

- **状态 Tab（6 个，业务/管理员双文案）**：全部、待核实（核实阶段）、待分发（分发阶段）、处置中（处置阶段）、待验收（验收阶段）、已销号；各 Tab 带计数徽标。

## 1.2 输入字段

本页无表单录入字段，仅含筛选控件输入（见 1.4）。

## 1.3 输出字段

主表格共 12 列，行数据由 `generateHazardRowsFromRecords()` 构造：

| 列 | 字段 | 说明 |
|---|---|---|
| 隐患名称 | hazardName | 房屋名称 + 隐患部位 + 隐患类型 |
| 隐患类型 | hazardType | 由部位映射（承重墙/木构架/楼梯间/阳台/梁柱/楼板→结构隐患，屋面→屋面隐患，地基基础→地基隐患，外墙→外围隐患，排水系统→设施隐患） |
| 隐患等级 | hazardLevel | 归一后三分类文案 + risk-badge 颜色（红/黄/蓝） |
| 隐患地址 | address | 省略号截断 |
| 上报来源 | source | 物联自动上报 / 巡查人员上报 / 排查发现 / 群众举报 / 专家研判 |
| 上报人 | reporter | 取产权人 |
| 处置单位 | dutyUnit | responsibleDept 或"街镇+城建中心" |
| 处置人 | dutyPerson | — |
| 上报时间 | reportTime | YYYY-MM-DD HH:mm |
| 产权人 | ownerName | — |
| 状态 | status.label | status-tag 颜色（红/橙/蓝/紫/绿/灰） |
| 操作 | — | 管理员视图列头为"详情" |

## 1.4 查询条件

| 条件 | 控件 | 说明 |
|---|---|---|
| 隐患名称/地址 | 文本框 | 模糊匹配（includes） |
| 隐患等级 | 下拉框 | 全部 / 严重安全隐患（第三类）/ 一定安全隐患（第二类）/ 未发现安全隐患（第一类），精确匹配 |
| 处理状态（管理员视图为"流转阶段"） | 下拉框 | 全部 / 待核实 / 待分发 / 处置中 / 待验收 / 已销号 / 已驳回，精确匹配 |
| 查询 | 按钮 | 应用筛选 |
| 重置 | 按钮 | 清空三项筛选并重新过滤 |

过滤顺序：先按当前 Tab（status.key）过滤，再依次按名称/地址、隐患等级、处理状态过滤。

## 1.5 数据生命周期

- **读取**：`initHouseArchSeed()` 初始化种子数据 → `getAllHouseRecords()` 获取全量房屋记录 → 过滤农村自建房 → 生成隐患行（`hazardNo = 唯一标识 + '-H' + 序号`）。
- **写入**：本页不写库，所有操作为页面跳转。
- **状态映射 `mapStatus(governance, closeStatus)`**：

| 条件 | key | label | 颜色 |
|---|---|---|---|
| closeStatus=已通过 | closed | 已销号 | 绿 |
| closeStatus=已驳回 | reject-check | 已驳回 | 灰 |
| closeStatus=审核中 | pending-accept | 待验收 | 紫 |
| governance=done | pending-accept | 待验收 | 紫 |
| governance=doing/overdue | handling | 处置中 | 蓝 |
| governance=pending 及其他 | pending-audit | 待核实 | 红 |

## 1.6 业务规则

1. 列表仅展示来源为"巡查人员上报""排查发现""群众举报"的农村自建房隐患；物联与专家研判来源由其他入口管理。
2. 隐患等级显示统一归一为三分类口径（严重/一定/未发现安全隐患），历史名称按映射表转换。
3. KPI 卡片统计基于原始 hazardLevel 值（重大/较大/一般/第三类/第二类/第一类/安全/无风险）。
4. 管理员视图为只读总览，不展示核实/分发/处置/验收操作按钮，仅可查看详情。
5. 业务视图下每个状态行仅显示单个主操作按钮，不并列"查看"按钮。

本页无弹窗与异常提示文案；空列表时表格区域展示空态；KPI 计数为 0 时正常显示 0。

# 第 2 章 风险隐患核实（rural-warning-audit.html）

## 2.1 功能概述

风险隐患核实页（页面标题"农村自建房 - 风险隐患核实"，图标 fa-clipboard-check）用于对待核实隐患进行核实决策：核实通过（确认隐患等级并填写核实意见）、驳回/退回（填写原因）、或申请专家/机构评估。页面为左右双栏布局（左 1fr + 右 380px sticky），顶部为"隐患状态流转"6 节点横向步骤条。

- **入口**：风险隐患管理页"核实"按钮，URL 参数 `?no={houseNo}`。
- **返回**：页头右侧"返回风险隐患管理"。
- **左列 3 个 Tab**：基础信息（隐患基础信息 + 现场照片 + 风险详情）、房屋信息（房屋信息 + Leaflet 真实地图 + 纠偏工具栏）、检查记录（检查记录表）。
- **右列**：隐患核实决策卡 + 流转记录时间线。
- **浮层**：专家评估面板（右侧滑出 480px + 遮罩）。

## 2.2 输入字段

### 2.2.1 隐患核实决策卡

| 字段 | 控件 | 必填 | 枚举/默认 | 显示分支 |
|---|---|---|---|---|
| 决策选项 | 3 个决策卡片单选 | 是 | 核实通过 / 驳回退回 / 申请专家/机构评估；默认无选中 | 全局 |
| 隐患等级确认 | 下拉框 | 是 | 请选择 / 严重安全隐患（red）/ 一定安全隐患（yellow）/ 未发现安全隐患（blue） | 选"核实通过"展开 |
| 核实意见 | 多行文本框 | 是 | placeholder"请输入核实意见..." | 选"核实通过"展开 |
| 驳回/退回原因 | 多行文本框 | 是 | placeholder"请输入驳回/退回原因..." | 选"驳回/退回"展开 |

### 2.2.2 专家评估面板

| 字段 | 控件 | 必填 | 枚举/默认 |
|---|---|---|---|
| 申请类型 | 单选 name=expertType | 是 | 专家评估（默认选中）/ 机构鉴定 |
| 评估目的 | 多行文本框 | 是 | 描述评估目的和背景 |
| 评估要求 | 多行文本框 | 否 | 评估范围、重点内容、完成时限等 |
| 建议专家/机构 | 文本框 | 否 | 专家姓名或机构名称 |
| 附件材料 | 文件选择（multiple，隐藏 input） | 否 | 支持 PDF、Word、图片等，单个文件不超过 50MB |

### 2.2.3 地图纠偏输入

| 字段 | 控件 | 说明 |
|---|---|---|
| 纠偏后坐标 | 拖拽标记 / 点击地图选点 | 经纬度取 6 位小数（toFixed(6)），写回 rec.lat / rec.lng |

## 2.3 输出字段

- 检查记录表列：检查时间、检查类型（默认"日常检查"）、检查人、检查结果、检查结论；空态"暂无检查记录"。
- 流转记录时间线：隐患上报 → 检查排查 → 任务分配（user/time/desc）。
- 坐标展示：经度、纬度、位置描述（house-lat / house-lng / house-location）。

## 2.4 查询条件

本页为单记录操作页，无查询条件。记录通过 URL 参数 `no` 唯一定位。

## 2.5 数据生命周期

1. **读取**：`getUrlParam('no')` → `initHouseArchSeed()` → `getHouseRecord(no)`。
2. **暂存**：`saveDraft()` 仅前端提示"已暂存"，不落库（当前实现）。
3. **提交**："确认提交"按钮当前无绑定事件（源文件在 2251 行物理截断，loadData 尾部缺失），需求上应执行：校验决策分支必填项 → 写回核实结论 → 状态流转（通过→待分发；驳回→已驳回）。
4. **地图纠偏持久化**（saveMapCorrection）：
   - 本地：写回 `currentRec.lat/lng` → `getHouseArchStorage()` 更新对应房屋 → `setHouseArchStorage()`；
   - 服务端：`POST /api/houses/{no}/coordinates`，body `{lat, lng}`，写入 `data/house-corrections.json`；
   - 成功提示"坐标纠偏已保存"；服务端返回错误时提示"坐标已保存到本地，但服务端返回错误：{error}"；网络失败提示"坐标纠偏已保存到本地"。

## 2.6 业务规则

1. 核实通过必须确认隐患等级（三分类）并填写核实意见。
2. 驳回必须填写驳回/退回原因，驳回后隐患退回上报环节或标记为已驳回。
3. 申请专家/机构评估需选择申请类型并填写评估目的，保存后保持专家评估选中态。
4. 地图纠偏为核实环节的辅助能力：仅在房屋记录含经纬度时初始化地图；纠偏模式下可拖拽标记或点击地图选点；退出纠偏时若未保存则恢复原始坐标。
5. 隐患状态流转条节点时间推算规则：上报时间 → +24h 核实 → +2h（或管理记录 assignTime）分发 → +4h 开始处置 → 分发后 10 天提交验收 → 再 +24h 销号；进度条宽度 = 当前节点序号/5×100%，已完成节点绿色、当前节点蓝色。

| 暂存 | alert"已暂存" |
| 确认提交 | （当前无绑定，需求见 2.5） |
| 地图图层切换 | 街道图（OSM）/ 卫星图（Esri）/ 默认离线网格底图（canvas 绘制"离线网格底图 z/x/y"），maxZoom 18 |

## 2.9 权限与审计

- 仅具备核实权限的角色（如区级管理员、按流程配置的核实处理人）可执行核实决策。
- 纠偏保存需记录操作审计：操作人、操作时间、原坐标、新坐标（当前版本仅写坐标值，审计字段待补）。

## 2.10 埋点要求

当前版本未实现埋点。建议补充：核实决策提交埋点（决策类型、等级）、专家评估申请埋点、地图纠偏保存埋点（含图层类型）。

## 2.11 验收标准

1. 进入页面后正确加载隐患基础信息、现场照片、风险详情、房屋信息与检查记录。
2. 顶部状态流转条正确定位当前节点（待核实），已完成节点绿色、当前节点蓝色。
3. 选择"核实通过"展开等级确认与核实意见表单，两项必填校验生效。

# 第 7 章 隐患流程配置（rural-flow-config.html）

## 7.1 功能概述

隐患流程配置页（页面标题"农村自建房 - 隐患流程配置"，图标 fa-house-chimney）用于按隐患来源配置农村自建房隐患流转流程中各节点的处理人分配策略。页面无面包屑、无 KPI 卡片、无筛选、无表格、无弹窗；顶部为 4 个来源 Tab，主体为 6 个固定流程节点的纵向时间线配置区，页面级操作为"重置"与"保存配置"。

- **4 个来源 Tab**：排查发现（默认）、巡查人员上报、群众举报、专家研判（各带计数徽标 6）。
- **6 个固定流程节点**（不可增删）：隐患上报 → 隐患审核 → 隐患分发 → 隐患接收 → 隐患处置 → 隐患验收。

## 7.2 输入字段

每个流程节点可配置以下字段：

| 字段 | 控件 | 适用节点 | 枚举/默认 |
|---|---|---|---|
| 分配策略（strategy） | 下拉框 | 全部 6 节点 | 按系统角色分配 / 按房屋属地（街镇/村）分配 / 按产权人分配 / 按隐患上报人分配 / 按第三方鉴定机构分配 |
| 处理角色（role） | 下拉框 | 全部 6 节点 | 区级管理员 / 街镇城建中心管理员 / 村级网格员 / 产权人 / 第三方鉴定机构 / 巡查人员 / 专家 |
| 驳回策略（rejectStrategy） | 下拉框 | 审核、接收、验收节点 | 退回上一节点 / 退回初始上报人 |
| 允许退回（allowFallback） | 复选框 | 分发节点 | 是/否 |
| 自动通过（autoApprove） | 复选框 | 审核、分发节点 | 勾选后同人自动过审（如分发人与审核人为同一人时审核自动通过） |
| 自动分发（autoDispatch） | 复选框 | 仅分发节点 | 勾选后审核通过免人工分发，按策略自动分配 |

默认配置示例（DEFAULT_CONFIGS，4 来源 × 6 节点）：群众举报的"隐患上报"节点默认"按隐患上报人分配/村级网格员"；专家研判的"隐患审核"节点默认"区级管理员"；各来源"隐患验收"节点默认"第三方鉴定机构/退回初始上报人"。

## 7.3 输出字段

- 节点时间线展示：节点序号、节点名称、当前配置的策略与角色摘要、节点内联提示（说明同人自动过审、免人工分发等规则）。

## 7.4 查询条件

本页无查询条件。来源 Tab 即配置维度切换（switchSource）。

## 7.5 数据生命周期

1. **初始化**：`currentSource='inspection'`，`configs` 为 DEFAULT_CONFIGS 深拷贝，`renderTimeline()` 渲染当前来源的 6 节点配置。
2. **编辑**：`updateConfig(nodeId, field, value)` 更新内存中对应来源、对应节点的字段值。
3. **保存**：`saveConfig()` 当前仅 console.log + alert"农村自建房隐患流程配置已保存（当前来源：{来源名}）"，**不写 localStorage、不调用 API**（演示态）。需求上应将 4 来源 × 6 节点配置持久化，供预警流转引擎读取。
4. **重置**：confirm"确定要重置当前来源的农村自建房默认流程配置吗？"确认后恢复当前来源默认配置。
5. **主题同步**：通过 `message`/`setTheme` 与框架页同步主题。

## 7.6 业务规则

1. 流程节点固定为 6 个，不支持新增、删除或调整顺序。
2. 配置按隐患来源隔离，4 个来源各自维护一套 6 节点配置。
3. 分配策略与处理角色组合使用：选择"按系统角色分配"时角色必选；选择"按产权人/隐患上报人/第三方鉴定机构分配"时处理人由业务对象决定。
4. 驳回策略仅在含驳回能力的节点（审核、接收、验收）展示。
5. "自动通过"勾选后，当相邻环节处理人为同一人时系统自动过审，减少重复操作。
6. "自动分发"勾选后，审核通过即按分发节点配置策略自动分配，无需人工干预。
