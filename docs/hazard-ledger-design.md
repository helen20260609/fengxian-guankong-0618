# 隐患台账（Hazard Ledger）设计文档

> 状态：设计稿 v1 — 待评审
> 日期：2026-10-14
> 目标页：`pages/house-arch-detail-rural.html`
> 触发：治理链路"隐患动态"模块独立化 + 排查/隐患数据模型分离

---

## 一、业务模型转变

### 现状（快照模型，待废弃）
```
排查记录 ──派生──> 风险记录 ──1:1锁定──> 治理事件
   │                                    │
   └─ 每次排查重新生成一批记录      └─ addDanger 是单对象，一坨隐患混一起
```
问题：
- 隐患没有独立身份，只是排查结论的附属字段
- 连续两次排查都是第三类 → 重复生成了两条"风险记录"，实际是同一批隐患未闭环
- 治理事件挂在"风险记录（=一次排查的快照）"上，而不是挂在"隐患"上

### 目标（台账模型）
```
房屋 (1) ──< (N) 隐患记录 hazardRecords (1) ──< (N) 隐患动态 hazardDynamics
                ↑                                      ↑
排查 (N) ──登记/跟踪──> 隐患                    每次处置/复查追加流水
   │
   └─ 一次排查可：①新登记若干隐患  ②复查既有隐患（追加动态，不新建）
```

**三条核心规则**：
1. **隐患挂在房屋上，不挂在排查上** — 隐患记录一旦创建，独立存在，有自己的 ID/状态/当前管控
2. **排查是"跟踪动作"** — 每次排查要么登记新隐患，要么对既有隐患追加一条动态记录（复查结论）
3. **闭环靠动态链** — 隐患从"新增→管控→跟踪→复查合格销号"是一条完整流水，动态记录就是证据链

### 三个断面的定位（对应截图）
| 断面 | 角色 | 回答的问题 |
|---|---|---|
| 新增隐患 | 隐患的**出生证** | 问题是什么、在哪个部位、现场影像、初判程度 |
| 隐患控制情况 | 隐患的**当前态** | 当前管控措施（第三类：人屋分离/封控；第二类：书面告知/限制用途） |
| 隐患动态记录 | 隐患的**流水账** | 每次处置/鉴定/复查按时间追加，是销号验收的证据链 |

## 二、数据结构设计

### 2.1 新增：隐患主档 `hazardRecords[]`
挂在房屋记录根级（`currentHouseArch.hazardRecords`），与 `inspectionRecords`/`patrolRecords` 平级。

```js
{
  id: 'HZ-NF-2025-00002-001',       // 隐患编号（房屋内唯一，不再随排查变化）
  houseNo: 'NF-2025-00002',

  // ── 出生证（新增隐患时录入，创建后不可改）──
  createdAt: '2026-10-13 15:30',
  createdBy: '周敏',
  sourceType: '排查',                 // 首次登记来源：排查/巡查/群众上报/上级交办
  sourceId: 'INS-NF-2025-00002-003', // 首次登记对应的排查/巡查记录 id
  hazardType: '墙体开裂变形',          // 隐患类型（ADD_DANGER_TYPES）
  hazardTypeOther: '',                 // 类型为"其他安全问题"时的补充说明
  location: '一层承重墙',              // 具体部位
  description: '承重墙体斜向裂缝，宽度约3mm',
  photos: [...],                      // 现场影像（数组，替代旧的 photosByType 字符串拼接）
  initialJudge: '第三类',             // 初判程度

  // ── 当前态（由最新动态/控制情况推导，冗余存储便于列表展示）──
  currentLevel: '第三类',             // 当前风险等级（可被后续复查调整）
  currentStatus: '管控中',            // 未管控/管控中/整治中/已销号
  controlMeasure: '人屋分离+停止使用+围挡封控+警示标示',  // 当前管控措施摘要
  controlUpdatedAt: '2026-10-13 16:30',

  // ── 闭环 ──
  closedAt: '',                       // 销号时间（空=未闭环）
  closeAuditId: '',                   // 关联的销号审核记录
}
```

### 2.2 新增：动态流水 `hazardDynamics[]`
每条隐患的处置/复查流水，按时间追加，永不修改（只增不改）。

```js
{
  id: 'DYN-HZ-...-001',
  hazardId: 'HZ-NF-2025-00002-001',   // 挂在哪条隐患
  actionType: '登记',                  // 登记/管控落实/鉴定/工程整治/复查/销号
  actionTime: '2026-10-13 15:30',
  operator: '周敏',
  org: '西渡街道城建中心',
  content: '排查发现承重墙体开裂，初判第三类',   // 本次动作描述
  conclusion: '确认安全隐患',                    // 本次结论
  levelAfter: '第三类',                          // 本次动作后的风险等级
  photos: [...],
  sourceType: '排查',                  // 关联来源（复查时对应排查记录）
  sourceId: 'INS-NF-2025-00002-003',
}
```

### 2.3 排查/巡查记录的角色变化
`inspectionRecords[]` / `patrolRecords[]` **保留不动**，但增加关联字段：

```js
// inspectionRecords[i] 新增：
linkedHazardIds: ['HZ-...-001', 'HZ-...-002'],  // 本次排查涉及的隐患（新登记+复查）
newHazardIds: ['HZ-...-002'],                    // 其中本次新登记的
reviewHazardIds: ['HZ-...-001'],                 // 其中本次复查的
```

→ **排查详情页 = 本次排查事件 + 涉及的隐患清单**（双向跳转）

### 2.4 治理事件的挂载点迁移
```
旧：governanceEvents[].riskRecordId  → 挂在"一次排查快照"
新：governanceEvents[].hazardId     → 挂在"一条隐患"
```
- `GE-{hazardId}`，一条第三类隐患一个治理事件
- 隐患闭环（销号）= 治理事件 `closeStatus === '已通过'`
- `riskRecordId` 字段保留作迁移兼容（标记该事件由哪次排查触发创建）

### 2.5 风险记录 `riskRecords[]` 的角色
**从"快照档案"降级为"排查事件日志"**：
- 每次排查仍生成一条（保留现有派生逻辑）
- 但不再 1:1 绑定治理事件，而是聚合显示"本次排查跟踪了几条隐患/新登记了几条"
- 状态列改为：本次排查涉及的隐患中，最严重的未闭环等级

## 三、页面结构调整

### 3.1 一级 TAB 变化
```
旧：房屋概况 | 风险发现 | 风险信息记录 | 应急处置
新：房屋概况 | 风险发现 | 风险信息记录 | 隐患台账 | 应急处置
                                        ^^^^^^^^
                                        新增（从治理链路抽出）
```

### 3.2 「隐患台账」页内部结构
```
隐患台账（一级TAB）
├── 隐患列表（表格，每行一条隐患，不是一次排查）
│     列：隐患编号 | 类型 | 部位 | 初判等级 | 当前状态 | 管控措施 | 登记时间 | 操作
│     状态徽章：未管控(灰)/管控中(橙)/整治中(蓝)/已销号(绿)
│
└── 选中隐患 → 下方展开详情，内嵌二级胶囊TAB：
      ├── 基本信息     （出生证：类型/部位/描述/影像/初判）
      ├── 隐患控制情况  （当前管控措施，可编辑）
      ├── 隐患动态记录  （流水表格，追加式，证据链）
      └── 治理链路     （仅第三类：鉴定/计划/措施/验收/销号 —— 复用现有 renderGovernanceBody）
```

### 3.3 「风险信息记录」页变化
- 列表保持现有样式（每行=一次排查），但**状态列语义改**：
  - `未闭环` = 本次排查涉及的隐患中，存在未销号的
  - `已闭环` = 本次排查涉及的隐患全部已销号
  - `无隐患` = 本次排查结论第一类，未登记任何隐患
- 详情区底部新增"**本次排查涉及的隐患**"清单（卡片列表，点击跳到隐患台账对应行）
- 删除现有的"治理链路"内嵌二级TAB（`renderRiskGovernanceTabs` 整体搬迁到隐患台账）

### 3.4 「风险发现」页变化
- 排查登记详情底部新增"**本次排查登记的隐患**"清单
- 新增/编辑排查记录时，表单末尾增加"登记隐患"区块：
  - 勾选隐患类型 → 每种类型一组照片上传（复用现有 addDanger UI，但改为多隐患数组）
  - 每条隐患独立设置部位/初判程度/描述
  - 也可勾选"复查既有隐患"→ 弹出隐患选择器 → 填写本次复查结论

## 四、迁移策略（兼容现有 mock 数据）

### 4.1 数据迁移函数 `migrateToHazardLedger(rec)`
幂等，在 `getCurrentHouseArch` 后自动执行：

1. **扫描现有治理事件**：每个 `ev`（挂 `riskRecordId`）→ 找到源头排查记录 → 生成一条 `hazardRecord`（`sourceId = rr.sourceId`，`initialJudge = rr.riskLevel`），把 `ev.data` 平移过来
2. **拆分 `addDanger` 单对象**：`ev.data.addDanger.types[]` 每个类型 → 独立隐患记录
3. **`hazardDynamics` 初始化**：为每条隐患生成第一条"登记"动态（从 `createdAt`/`createdBy` 推导）
4. **`riskRecords[i].linkedHazardIds`** 回填
5. 迁移完成后打标记 `rec._hazardLedgerMigrated = true`，下次跳过

### 4.2 兼容期
- 旧字段（`addDanger` 单对象、治理事件挂 `riskRecordId`）保留可读，不再写入
- `__riskRecordStatus` 改为读隐患闭环状态，不再读治理事件措施完成度
